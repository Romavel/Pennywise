# Pennywise — Personal Finance

A Flutter app for tracking income, expenses and monthly budgets, backed by Firebase.

> Status: **stage 4 — dashboard.** Authentication, transactions in Cloud Firestore and a dashboard with the all-time balance, monthly totals, spending by category and recent transactions. Budgets, reports and settings come next.

## Stack

Flutter · Riverpod · go_router · Firebase (Auth, Cloud Firestore) · fl_chart · intl · Freezed / json_serializable · mocktail

## Project structure

```
lib/
  main.dart                  entry point, reads build config
  firebase_options.dart      generated by `flutterfire configure` (placeholder until then)
  app/
    app.dart                 MaterialApp.router
    router.dart              routes, bottom-nav shell, splash redirect
    routes.dart              route paths
    providers.dart           app-wide providers (config, Firebase init, theme mode)
    firebase_bootstrap.dart  Firebase + emulator setup
    theme/                   color tokens, typography, ThemeData
  core/
    config/  errors/  utils/  widgets/  constants/
  features/
    auth/ dashboard/ transactions/ categories/ budgets/ reports/ settings/
      data/  domain/  presentation/
docs/design/                 screen mockups and design tokens
```

Views never talk to Firestore directly: presentation → Riverpod providers → repositories (data layer).

## Getting started

1. Install Flutter (stable) and the Firebase CLI, then the FlutterFire CLI:
   ```bash
   dart pub global activate flutterfire_cli
   ```
2. Create a Firebase project and connect the app (this overwrites `lib/firebase_options.dart`):
   ```bash
   flutterfire configure --platforms=android,ios
   ```
3. In the Firebase console enable **Authentication → Sign-in method → Email/Password** and create a **Firestore Database** (production mode).
4. Deploy the Firestore Security Rules:
   ```bash
   firebase deploy --only firestore:rules --project <your-project-id>
   ```
5. Run:
   ```bash
   flutter run
   ```

Until step 2 is done the splash screen shows a "Firebase is not configured" message.

`lib/firebase_options.dart` and `android/app/google-services.json` are committed. They identify the Firebase project and are not secrets; access to data is enforced by Firebase Authentication and Firestore Security Rules. Restrict the API keys to the app in Google Cloud Console before a public release.

### Build configuration

| `--dart-define` | Values | Default |
|---|---|---|
| `APP_ENV` | `dev`, `prod` | `dev` |
| `USE_FIREBASE_EMULATORS` | `true`, `false` | `false` |
| `FIREBASE_EMULATOR_HOST` | host name | `10.0.2.2` on Android, `localhost` elsewhere |

Emulators are refused in `prod` builds.

### Local Firebase emulators

```bash
firebase emulators:start
flutter run --dart-define=USE_FIREBASE_EMULATORS=true
```

Emulator UI: http://localhost:4000. Firestore rules live in `firestore.rules` (deny-all baseline; owner-scoped rules are added per feature).

## Data model

Each user's data lives under `users/{uid}`. Transactions are stored in `users/{uid}/transactions/{id}`:

| Field | Type | Notes |
|---|---|---|
| `type` | `"income"` \| `"expense"` | |
| `amountMinor` | int | amount in the smallest currency unit (4599 = 45.99 PLN), always > 0 |
| `currency` | string | ISO 4217 code, fixed after creation |
| `categoryId` | string | stable id, e.g. `food`, `salary` |
| `note` | string | up to 200 characters, may be empty |
| `occurredAt` | timestamp | date of the transaction |
| `createdAt`, `updatedAt` | timestamp | set by the server |

The list queries one month by `occurredAt`; type, category and note search are applied on the device, so no composite indexes are needed. The dashboard's all-time balance listens to all of the user's transactions (served from Firestore's local cache after the first load); for very long histories this would move to a server-maintained running total.
